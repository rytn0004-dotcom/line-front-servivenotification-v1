# LINE 客服系統 V2.9.20

本版重點：綁定流程與「綁定審核」資料流重新對齊，避免超過3分鐘反悔期後讓使用者先輸入新姓名而繞過管理員審核。

## 綁定正式流程

首次綁定：
1. 輸入「綁定」／① LINE綁定。
2. 家長回覆「家長」，老師回覆「老師」。
3. 家長輸入學生姓名；多位學生使用「、」分隔。老師輸入系統登記姓名。
4. 確認後寫入「聯絡人」，「綁定暫存」改為 `BOUND`。
5. 課表查詢權限預設為「否」。
6. 首次確認前最多可重新輸入 3 次。

3 分鐘反悔期：
- 綁定完成後 3 分鐘內可「更正綁定」一次。
- 使用者可直接輸入新資料並確認。
- 更正完成後重新建立 3 分鐘反悔期，課表查詢權限重置為「否」。

超過 3 分鐘：
1. 使用者輸入「更正綁定」／「重新綁定」。
2. 系統**先建立「綁定審核」申請**，不要求使用者先輸入新的學生／老師姓名。
3. 管理員在「綁定審核」將「管理員結果」填為「核准」或「拒絕」。
4. 核准後，使用者下一次操作時才會進入輸入新資料狀態。
5. 使用者輸入新資料並再次確認後，才正式更新「聯絡人」與「綁定暫存」。
6. 拒絕則維持原綁定。
7. 使用者取消則維持原綁定，審核列標記為已取消。

## Excel 一致性

程式支援正式「聯絡人」工作表欄名「學生姓名/關聯」，也相容「學生姓名/關聯（可多位）」；「綁定審核」固定使用以下 10 欄：

`申請時間｜LINE User ID｜LINE 顯示名稱｜身分｜目前綁定｜申請變更｜申請狀態｜管理員結果｜處理時間｜備註`

ZIP 不包含 Excel；本次另提供同步更新的 V2.9.20 Excel。

## 舊資料相容

V2.9.20 會偵測舊版遺留的 `WAIT_ADMIN_REBIND_VALUE`／`flow=adminRebind` 且尚未建立審核的狀態，先補建「綁定審核」，不會直接讓舊流程繞過管理員審核。

## Render

Start Command：`node server.js`

部署後建議依序測試：
`① LINE綁定 → 家長 → 學生姓名 → 確認`
`→ 3分鐘內「更正綁定」`
`→ 超過3分鐘「更正綁定」→ 查看「綁定審核」→ 管理員核准 → 輸入新姓名 → 確認`

## Rich Menu 模組（獨立、可選）

本版本另外加入 `richmenu/`，不取代原本的 LINE 客服邏輯，也不新增 npm 套件。`RICH_MENU_ENABLED` 預設為 `false`，因此只要不開啟 Render 變數，現有服務行為不會因 Rich Menu 模組而改變。

啟用時，在 Render Environment Variables 加入：

```text
RICH_MENU_ENABLED=true
RICH_MENU_CONFIG_PATH=richmenu/richmenu.json
RICH_MENU_IMAGE_PATH=richmenu/richmenu.png
```

Rich Menu 會在服務啟動時依序進行「驗證 → 查找相同版本 → 必要時建立 → 上傳圖片 → 設為 Default」。設定與圖片都沒有改變時會重用現有 Rich Menu；因此 Render 重啟不會每次建立新選單。

Rich Menu 的按鈕使用既有文字指令（1、2、4、5、6、功能選單），點擊後仍由原本 `/webhook` 處理，因此不需要新增第二個 webhook。

如需換成正式設計，只需替換 `richmenu/richmenu.png`，並依新按鈕位置調整 `richmenu/richmenu.json` 的 `areas`；LINE 目前要求 Rich Menu 圖片為 JPEG/PNG、寬度 800–2500px、高度至少 250px、長寬比至少 1.45，檔案大小上限 1 MB。citeturn887434search5
